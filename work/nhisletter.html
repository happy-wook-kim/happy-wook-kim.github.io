Case study

국민건강보험공단 명절카드

국민이 직접 만들어 보내는 공식 명절 인사 카드

역할
개발 · 인프라 · 배포 · 운영
클라이언트
국민건강보험공단
유형
공식 캠페인 웹사이트
스택
React 19 · TypeScript · Vite · PHP · MySQL · nginx
도메인
nhisletter.kr

카드를 고르고 문구를 넣으면 그 자리에서 이미지로 합성돼, 저장하거나 카카오톡으로 보낼 수 있는 사이트입니다. 화면 개발만이 아니라 서버 구축부터 도메인·HTTPS·배포 자동화·부하 대비·운영 모니터링까지 혼자 맡았습니다. 2만명 대상 발송을 서버 오류 없이 넘겼고, 캠페인 기간 내내 운영하고 있습니다.

In production

SCALE

발송 당일 8.8만 요청, 45.5GB

피크는 분당 4,182건. 가장 몰린 순간에도 서버 오류(5xx)는 단 한 건도 없었습니다.

RESULT

하루 2,300건, 캠페인 3만 건 규모

국민이 직접 문구를 써서 만든 카드입니다. 안내가 나간 첫날에만 2,300건이 저장·공유됐습니다.

PERFORMANCE

방문자당 1.8MB

2만명이 한꺼번에 들어올 것을 계산해, 전달받은 9MB 애니메이션 카드를 목록용 정지 이미지로 따로 만들었습니다. 그대로였다면 120GB가 나갔을 트래픽입니다.

OWNERSHIP

서버까지 혼자

클라우드 인스턴스 생성, HTTPS 발급·자동갱신, 배포 스크립트, 요청 제한, 정리 자동화까지 직접 구성했습니다.

Problem solving

01

카카오톡에서 저장이 안 되던 문제

카카오톡 인앱 브라우저는 일반적인 방식의 이미지 저장을 지원하지 않습니다. 다운로드가 시작되는 것처럼 보이다 조용히 사라졌습니다. 원인을 찾아 서버가 직접 파일을 내려주는 방식으로 바꿨습니다. 카카오톡으로 들어온 이용자들이 그 뒤로 정상 저장하고 있습니다.

02

9MB 애니메이션 카드

클라이언트가 전달한 움직이는 카드가 9MB였습니다. 카드를 고르는 목록에서까지 원본을 받을 이유가 없어, 첫 프레임을 뽑아 정지 이미지를 따로 만들었습니다. 결과 화면에서는 원본 그대로 움직입니다.

03

같은 순간에 만든 카드가 섞이던 문제

파일 이름이 밀리초까지만 달라, 동시에 저장한 두 사람의 카드가 서로 덮어써질 수 있었습니다. 남의 인사말이 전달될 수 있는 문제라 이름 규칙부터 바로잡았습니다.

04

발송 전 부하 대비

2만명이 몰릴 상황을 계산해 서버 사양·동시 처리량·요청 제한을 미리 조정했습니다. 실제 피크는 분당 4,182건이었고 여유 있게 넘겼습니다.

05

발송 뒤에도 계속 도는 서비스

캠페인이 끝날 때까지 접속은 이어집니다. 오래된 파일을 자동으로 정리하고, 인증서 갱신·디스크·응답 상태를 계속 지켜보고 있습니다.

국민건강보험공단 공식 사이트로, 2026년 추석 캠페인 기간 동안 운영되고 있습니다.
